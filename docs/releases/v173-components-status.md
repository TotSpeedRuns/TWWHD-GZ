# Experimental v173 authored component snapshot

This source-only snapshot preserves the selected authored components of the
experimental v173 practice test. The complete reproducible native-game builder
is not reconstructed here, and Source715 is not promoted. The earlier v171
renderer source is included byte-for-byte as a build dependency, together with
its original strict builder and header/tool boundary.

The selected plan has 28 objects and 104 packed hooks. Twenty-seven objects can
be rebuilt solely from the authored files and explicit compiler/WUT inputs.
The capacity-text object additionally requires five exact owned EUR language
packs. Its original localized messages, extracted message JSON and generated
C source are excluded. An authored local generator creates the private text
source outside the repository, and the same strict builder checks its exact
selected object identity. Toolchains, objects, game assets, installer recipes,
memory captures and console logs are not distributed.

The selected work covers the existing partial Rando Mode contexts, indexed
renderer, tracker writer adapters, startup reservation context and retained
menu-input diagnostics. Mode enable retains the existing Command Melody grant
path. The later all-items kit and new physical-admission implementation are
absent. This does not implement every upstream randomizer gameplay difference.
The HD randomizer's pinned MIT attribution is retained in the component;
upstream USA addresses do not establish current EUR interfaces.

The user observed playable v172 after Repair but could not open the GZ menu.
Offline review subsequently found missed compiler-inlined tracker writers;
v173 corrects those routes and retains input/guard/frame observations for the
next hardware test. The cause of the menu failure remains unresolved. The
source rebuild does not establish hardware boot, menu behavior, Save/Restore,
memory capacity, superswim timing or a resolved lag problem. Existing source
comments retain their original authoring-time context; build-spec.json names
the exact selected objects and the current limitations.

Run the commands in
[the component README](../../experiments/maintained-components/rando-mode-v173/README.md).
The source driver uses exact whole ELF and allocated-byte/ABI/relocation hashes,
complete compiler dependency scans, source/header/tool identities and an explicit
environment. All genuine SDK/native interfaces remain unresolved; no substitute
success providers are exported. The pinned Windows compiler runtime itself is
outside the stated closure. The old snapshots retain their original scopes.

The two public Python parser dependencies preserve their reviewed CRLF bytes.
Their semantic content is unchanged from main; targeted -text attributes retain
those exact bytes alongside the byte-pinned builders. Other dirty local work is
outside this curated export.
