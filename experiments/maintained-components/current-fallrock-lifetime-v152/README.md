# Current-only falling-rock lifetime recovery (v152)

This is the authored, compiled profile 422 extension used by the v152 test
release. It extends the existing current-only ItemNo 0/1 recovery transaction;
it does not delete arbitrary actors or reconstruct a missing saved actor.
The complete reproducible integrated public builder remains **v126**. These
includes and the exact patch are a partial maintained component, not a current
standalone runtime or an alternative ownership provider.

An eligible current-only falling rock must have a fresh live process identity,
complete native phase, matching layer, process allocation, solid-heap generation,
model and resident resource. Each followed dynamic envelope is checked through
the existing real ownership APIs. The class is admitted only inside the original
typed inverse or fresh native lifecycle writer interval. Profile number alone
is insufficient. The old profile 255 ItemNo 0/1 paths remain in the source.

The private intent remains2,328 bytes, with at most 8 actors and 32 contacts. Its
existing policy bytes distinguish profile 255 ItemNo 0/1 from the new class; the
private intent version becomes3. There is no new saved-state format, storage
bank, arbitrary deletion API or source publication waiver.

The ordinary engine's existing native deletion is issued once. Old actor/model
storage is never followed after issue. Original-generation process, collider
and heap completion records must finish before the existing same-Source
continuation issues one fresh ordinary world transaction. It reacquires the
real frame, owner, Source lease, job and all typed restore participants. A
parked world is never published as a successful restore.

## Observed scope

Two separate closed private Cemu sessions each qualified one current422 rock
and one contact, one Restore confirmation, genuine native retirement and a
fresh automatic same-Source request. The baseline class extension observed
38.063 seconds; the selected v152 runtime observed38.235 seconds, with zero
observed player-position error and all 15 typed targets committed. The latter
capture took1.468 seconds. Saved Source bytes and six normal/disposable save
files retained their hashes. These are individual Cemu observations, not a
speed improvement, repeated-cohort benchmark, Wii U timing or full-game result.

The first observed case predates the separately exported issued-Source tuple
change; the selected v152 case includes it. The comparison shows **no latency
gain**. One rock/contact per case does not qualify a six-rock cohort, mixed
classes, arbitrary lifecycle states, queue waits, post-void recovery, missing
Keese construction, active particles, resource replay or cutscene restoration.
