# Same-worker SOURCE custodian

This authored partial source snapshot shares one genuine existing SO/OSA
acquisition across WCM admission, installation and ROH adoption in the same
native worker invocation. The complete reproducible integrated export remains
**v126**. This directory is not a standalone current-runtime builder or release.

The fixed key is the real request, frame, slot, current thread and native parent
invocation. Each operation rechecks the actual pin, allocation, used/capacity,
identity, generation, Row seal, digest and registry revision. It does not retain
a chooser or queued-frame lease. Existing CURRENT checks, full admission hash,
mandatory installer full-source publication and transaction-final verification
remain. Successful adoption transfers the actual existing pin to normal SOM
retirement; it does not release/reacquire or create a copied token.

The retained installer invokes three existing callbacks: slot, MCA and bflower.
Each fixed parameterless C entry authenticates its ordinal and runs the actual
old callback once, then accepts only an exact revision increment of one under
the same current pin/context. Install completion and adoption require all three.
The untagged callback refuses while custody is pending; outside custody the
three entries preserve the original generic operation. No return-PC inference,
supplied native result, hash waiver or callback skip is used. Pre-adoption
failure cancels only an authenticated idle pin. Unknown/pending failure retains
state and blocks acknowledgement/context expiry rather than selecting fallback.

The code depends on the real source-owner, OSA metadata, SOM, WCM and native WCT
producer in its original translation units. Those dependencies are not stubs or
positive test providers. Copy the five new authored files according to
`integration-pins.json`, then apply the zero-context patch to those exact LF
parent source hashes. Only the three custom GZ runtime BL substitutions are
included; no native method body or full runtime assembly is exported.

Private component review reproduced all three parent objects before compiling
the candidate, retained the display-policy owner and all old state, and found
no new native imports/hooks or repair state beyond the original 76-byte custody
and 16-byte native purpose. A private Cemu campaign completed three
saved-holstered/current-drawn sword restores through typed WCT. A separate
campaign passed three natural-expiry factory bomb recreations with exact
fuse/pose and fresh native identities. That bomb lane did not run WCT and had
no BMH services; it is a factory-path regression, not full world replay.
Stable post-campaign helper state is not a per-restore observation. The bomb
lane retained sixteen covered full-source evaluations; no bomb speedup is
claimed. Sword covered evaluations were seven versus nine in an earlier
campaign, a descriptive count rather than a controlled latency comparison.
Earlier failed once-only custody and temporary installer diagnostics remain
distinct evidence, not successful native coverage. No full-game, Wii U,
hardware timing, delivery or comparative speed claim is made.

`policy_cases.c` compiles only the exact scalar context/stage/ordinal predicates.
It checks reorders, duplicates, skipped callbacks and key drift without an SO,
native API, owner or lease success fixture. Source-contract tests check the
actual pin/revision/cancel/transfer obligations and sanitized file pins. This
does not simulate or qualify a successful native installation.

READ, WORLD, physical backing and whole-lifetime authority remain absent. No
game executable, artwork, native bytes, captured SOURCE, save, private profile,
host memory reader or original native method is included.
